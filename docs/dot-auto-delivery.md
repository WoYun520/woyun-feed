# 让 Dot 自动送来素材

目标链路是：**Dot 采集 → 私有收件箱 → 网站自动同步、去重 → 你选入精选**。独立投递权限不能读取你的收藏、主题或筛选结果，也不能选入精选、删除资料或修改网站。

**当前状态（2026-10-10）**：收件箱与浏览器自动同步已走通，真实浏览器连接及刷新恢复已检查。Dot 本次反馈没有可用的安全凭据入口，尚未发送 POST；用户也未看到相关配置入口。因此，Dot 自动发送尚未接通。不能把 Codex 的样本试投递当成 Dot 本人投递成功。

## 第一次连接

1. 网站顶部点 **待筛选**，在 **素材自动接收** 中粘贴你自己的接收码，点 **连接**。只需在这个浏览器连接一次；不要把接收码交给 Dot。
2. 先确认采集工具具有安全保存凭据并发送 HTTP 请求的实际入口。由用户在该入口配置独立投递密钥，不通过聊天、提示词、素材 JSON 或脚本源码传递。当前 Dot 尚未具备已确认可用的入口，先保留原素材文件。
3. 只有完成上述安全配置后，采集工具才能在采集完成时投递，并保留成功回执。网站打开时和打开期间会自动检查已经送达的批次，也可以点 **立即同步**。第一次新投递可能稍后才出现。

发送环节真正接通后，才可以不用下载 JSON 再手动导入。电脑或网站关着时，收件箱仍能接收已发出的投递；重新打开网站就会继续同步。

当前可讨论的替代方案是本机自动转发：Dot 交付 JSON，用户下载到专用文件夹，本机助手使用本机私有配置自动投递。它能省掉手动导入，但仍需点击下载；此助手尚未实现，也不是 Dot 全自动采集投递。

## 你仍然决定留什么

新素材只进待筛选。原帖重复就跳过，不改变你已经精选、略过或收藏的记录，也不覆盖旧热度和原始文字。只有你点击 **选入精选** 才改变筛选状态。

收件箱批次保留 30 天，从服务实际收到时计算。同步成功后的待筛选、精选和略过记录留在当前浏览器，不随云端批次过期而清空；仍建议定期做完整备份。不同设备可以读取收件箱，但各自的筛选决定不会自动同步。接收码不放进资料备份，清除浏览器数据后需重新连接。

每批最多 100 条、2 MB；本浏览器最多保留 300 条筛选记录。同步失败或容量不足时，不把该批次记为已处理，下次可重试；它在云端的 30 天保留期仍会正常结束，原始交付文件需由采集方另行保留。

点 **断开连接** 只清除这个浏览器的收件连接，不删除已经导入的材料，也不撤销 Dot 的投递密钥。撤销或更换密钥需维护者重新设置服务端密钥。

## 给采集工具的接口约定

- 地址：`https://woyun-feed-preview.hhzovo66.workers.dev/api/dot/inbox`
- 方法：`POST`
- 请求头：`Content-Type: application/json` 和 `Authorization: Bearer <投递密钥>`。密钥不能放进网址、正文或日志。
- 正文：既有 `woyun-feed:candidates` v1 JSON，且 `collector` 必须保留真实来源 `Dot` 或 `feedgrab`。顶层仅允许 `format`、`version`、`collector`、`collected_at`、`items`、`alternatives` 六个字段。2026-10-10 的本机试跑见 [采集试跑](history/feedgrab-intake-20261010.md)。
- 未知数字、时间保留 `null`，不能把点赞换算成收藏，也不能把建议写成亲自试过的经历。只投递公开、脱敏资料，不发送 Cookie、密码、密钥或私人原件。仓库里没有单独的 `dot-collection-brief.md`。
- `201`：服务收到新批次；`200` 且 `existing: true`：同一内容已收到。两者只代表投递完成，不代表已同步到浏览器、用户认可或公开发布。
- 回执包含批次 `id`、实际 `received_at`、`item_count`、`existing`。重试发送同一份正文，不更改采集时间来制造新批次。
- `400/413/415`：修正格式或拆批后再试；`401`：停止并报告连接密钥问题；`429/503` 或网络中断：保留原 JSON，间隔重试最多三次。失败要明确报告，不能声称已送达。

读取接口使用独立接收码，Dot 的投递密钥不具有读取权限。接口没有精选、删除、公开发布或账号管理操作。

单条 X 精华帖不走这个收件箱。Overheard 用同一把投递密钥调用 `POST /api/dot/pending`。账号池、池外作者和首页贴链接都先进入待筛选，不按粉丝数排序，也不当场放上公开首页。满 1 小时仍未人工处理会自动过审。昨日最被低估必须人工钉。调用方式见 [待筛选进料](pending-intake.md)，过审见 [待筛选过审](pending-review.md)。
## 维护者配置

`DOT_INBOX` 是与 `PUBLIC_FEED` 分开的私有存储。Worker 仅保存两把不同随机密钥的 SHA-256 值：`DOT_DELIVERY_TOKEN_HASH`、`DOT_REVIEW_TOKEN_HASH`；缺配置时拒绝访问，不退回公开文件。配置路径 `/api/dot/*` 优先经过 Worker，不能被静态资源接管。

原始密钥只保存在维护者本机的私有目录，不进入公开构建、项目资料备份或工作观察记录。重新配置服务端哈希可以撤销旧密钥；更换后需分别更新 Dot 和使用者浏览器。收件箱无需修改现有公开资料及每日更新计划。

这是新投递能力，不是给 Dot 开启采集定时器。Dot 是否能在每次采集结束后发送 HTTP 请求，仍需它实际返回一次成功回执才能确认。
