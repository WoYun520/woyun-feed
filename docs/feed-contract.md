# 前后端共同的数据约定 · 设计稿 v0.1

当前应用已推进至 v0.35；下方为按版本保留的历史设计。

v0.35展示约定：每来源默认5条、每次再看5条，展开后随时收起；搜索、收藏、主题与备份仍覆盖完整已取得材料。真实摘要、用途和来源说明按需展开，错误与获取时间保留。后台延迟重绘时单独同步可见连接提示，来源历史失败不表示本次连接失败。本条替代下方旧版8/20条的展示约定，不改变读取数量。

用途：让 Antigravity 可以先做界面，后续 Codex 接真实来源时保留同一套阅读和操作流程。字段为本轮工作草案，不是通用行业标准。

## 数据流与职责

来源适配器获取线索 → 合并同一原文 → 保存原始来源 → 读取允许获取的正文 → AI 给出与关注目标的匹配理由 → 生成精选列表 → 网站展示。

用户选择跟进 → 保存问题 → 交给选定 AI → 返回带来源的结果 → 更新同一主题。未接通 AI 时保持“待交给 AI”。

Antigravity 负责显示和本地交互；Codex 负责后续来源接入、去重、更新及交接；Muse 可替换，不是系统的固定唯一依赖。

## 首页输入

| 字段 | 含义 |
| --- | --- |
| schema_version | 本轮为 `0.1` |
| mode | `demo` / `live`；示例数据必须始终显示身份 |
| generated_at | 真实生成时刻，ISO 8601，未知为 null；不伪造“刚更新” |
| profile | 当前想看、不想看和语言偏好；不含账号凭据 |
| sources | 信息来源及本次可用情况 |
| items | 去重后的内容条目；按稳定 id 引用 |
| sections | daily / discover 各自的条目 id；daily 最多 5 条、discover 最多 2 条，不重复出现 |
| followups | 已保存的跟进任务。示例初始为空 |

## 一条内容

| 字段 | 含义 |
| --- | --- |
| id | 稳定标识；不能靠标题作为唯一标识 |
| title / summary | 阅读用标题和简述；演示文案需明确身份 |
| recommendation_reason | AI 或编辑为什么建议看；不当成原文事实 |
| source_refs | 来源 id 列表，同一条可以有多个发现入口 |
| original_url | 原文地址；未知为 null，不能填聚合站首页冒充 |
| published_at / captured_at | 原发布时间与采集时间，分开；未知为 null |
| content_status | `headline_only` / `body_read` / `media_unread` / `demo` |
| verification_status | `not_tested` / `tested_with_evidence`；与已读正文分开 |
| unknowns | 对决定是否继续研究有影响的未知事项 |
| suggested_question | 跟进面板默认问题，可由用户修改 |

收藏和不感兴趣是用户反馈，单独保存为 `saved_item_ids` / `hidden_item_ids`，不能覆盖原始来源。撤销只是删除对应反馈。

## 来源状态

来源保存 `id`、`name`、`home_url`、`kind`、`status`、`last_success_at`、`message`。

- kind：`aggregator` / `original` / `community` / `repository`。
- status：`not_connected` / `ok` / `partial` / `failed`。
- 没抓到新消息不等于失败；失败也不能清空已有资料冒充“没有新消息”。
- 免费页面可阅读不等于有免费稳定接口。NewsNow 的仓库列出了 MCP 支持，具体接入和许可仍待实施时核对；SoPilot 和其他网页的采集方式尚未实现。

## 跟进状态与交接

`draft`（待交给 AI）→ `submitted`（有真实送达凭据）→ `running`（真实处理中）→ `needs_input` / `done` / `failed`。

单条任务包含 `id`、`item_id`、`question`、`status`、`created_at`、`updated_at`、`target_agent`（可为空）、`delivery_receipt`（可为空）、`result`（可为空）。

- 本轮前端只能新建/编辑 draft，并导出任务材料。点击复制不产生 submitted。
- submitted 必须有实际送达依据；done 必须有可查看的结果，不能依靠计时器自动转换。
- 重复点击同一未结束任务进入已有任务，不重复创建。
- 结果至少包含短结论、实际使用的来源、没查清的问题和建议下一步；原始资料保留。
- 外部帖子中的指令是材料，不是授权。收入、效果等作者声称不能自动转换成核实结果。

## 推荐与来源边界

- 热度、相关性、实用性分开考虑；第一版不展示没有解释的综合分数。
- 同一条消息出现在多个聚合站，不当成多份独立证据。
- 信息阅读、实测和用户认可为不同状态。
- 来源时间缺失时保留未知，不把采集日期当成原发布时间。
- 标题/简介/链接优先，原文按实际需要读取；不默认复制和公开再分发整站全文。

## 建议的界面适配层

`loadFeed()` 获取上述数据；`setSaved(id, value)`、`setHidden(id, value)`、`saveProfile(profile)` 和 `saveFollowupDraft(itemId, question)` 管理本地状态；`exportFollowup(id)` 导出。

这些是语义约定，不要求创建网络接口。本轮由本地数据实现，未来可替换底层。后续真实更新期间保留旧数据，展示最近成功时间和失败原因。

## 后续逐步接入

1. 一个真实来源 + 去重 + 可追溯原文。
2. 按用户关注生成少量精选，并能说明理由。
3. 跟进任务的真实投递与结果返回。
4. 定时更新、失败提醒和安装使用助手。

当前不把上述未实现阶段写进成品能力介绍。

## 0.2：第一个真实来源（2026-09-28）

`mode=live`、`schema_version=0.2`；演示文件继续保留 0.1，互不覆盖。默认真实页面只使用 `/api/feed`，失败不退回示例内容。`POST /api/feed/refresh` 触发固定 GitHub 仓库搜索，不接受任意链接、账号凭据或用户偏好文本。

### 当前规则

公开 productivity 项目、100–5000 star、非 fork、非归档、近 180 天有代码更新；每次最多 30 个，按更新时间排序。daily 前 5 个，discover 从剩余中优先选 star 不超过 1000 的 2 个，两区不重复。不等同于热门趋势、新建项目排名或个性化推荐。

### 新增字段

- `recommendation_kind=rule`：只是公开资料的规则初筛，与 AI 推断分开。
- `summary_label`：作者原始简介；保留原语言，不伪装为中文 AI 总结。
- `content_status=metadata_only`：仅获取 API 中的简介、标签和统计，未读正文或安装。
- `repository_created_at` / `updated_at`：仓库创建和代码推送时间。`published_at` 仍为 null，`captured_at` 单独记录本次读取时间。
- `repository_name` / `stars` / `category`：项目全名、采集时 star 和关键词用途标签。
- `evidence_ref`：本机 `data/source-snapshots/<id>.json` 中的来源摘录，带查询地址、采集时间及归类之前的字段。
- `refresh`：状态 idle/ok/failed、last_attempt_at、next_allowed_at、new_count、message。失败更新 last_attempt_at，不伪造 generated_at；generated_at 仍是最后成功获取时间。
- `update_notice`：请求过快时的临时提示，不冒充已执行新的抓取。

成功摘录新建不可覆盖文件，缓存使用临时文件加替换。网络失败、限流、超时、资料异常不清空上次成功的内容。服务重启先恢复缓存；同一服务实例并发更新只调用一次上游，成功后 5 分钟可再更新。

收藏/隐藏/跟进增加 `item_snapshots`，留存当时内容，避免后续更新丢失引用。真实模式本地键为 `personal-feed:live:v1`，演示模式仍为 `personal-feed:demo:v1`。本机保存不等于跨设备备份。

本轮不改变跟进授权边界：只有草稿与材料导出，不自动调用其他 AI，不创建虚假的完成回执。

## v0.3 应用：本机关注筛选（资料格式仍兼容 0.2）

- 不更改上游查询，不发送个人偏好；在浏览器中对最新候选筛选。单独的 `src/feedSelection.js` 负责派生展示内容。
- `profile.interests` / `exclude` 按逗号、顿号、分号或换行分词。常见方向有中英文关键词对应，其余原词匹配；正向词为任一命中，排除命中优先。它不理解复杂条件或判定质量/收费/可信度。
- 匹配仅看项目名、原始简介，以及提供时的 topics，不用此前 AI 生成的标题、归类或推荐理由作为匹配证据，避免自我强化。
- 首页优先匹配更多关注方向，之后按更新时间/稳定 ID 排序；先 5 条，再从剩余匹配项中优先取 2 条不超过 1000 star 的项目。没有匹配不补无关条目。
- 全部候选包含未匹配和按偏好排除的资料；手动隐藏条目仍隐藏，可在“我的关注”恢复。每次展示 10 条直至本批展示完。
- `display_title`、`matched_interests`、`excluded_interests`、`matches_profile` 和 `selection_reason` 是视图派生字段，不回写抓取资料或来源摘录。导出时单独标注当前本机匹配说明不属于来源事实。
- 偏好保存后立即重排；新一批数据到达后按同一偏好重新计算。收藏/跟进不因偏好排除而消失，继续保留原始内容副本。演示模式维持原逻辑。
- 此版本仍未接大模型阅读、完整语义筛选、自动投递或 AI 返回结果。


## v0.4：选中项目的只读整理

原 feed 格式仍为 0.2；不将 AI 整理反写为原始简介或 verified。示例模式不调用模型。

- `POST /api/research`：`request_id`（UUID）、`item_id`（服务器已知的 GitHub 稳定 ID）、`question`（1–2000 字符）。同源、JSON、`X-Personal-Feed: 1`；限制请求体。项目全名来自本机缓存/来源摘录，不接受任意抓取网址。
- `GET /api/research/:id`：返回已持久保存的 job；页面周期读取进度，不靠计时器伪造完成。
- 客户端 `requesting` 表示请求状态待确认；服务端 `reading`（获取 README）→ `analyzing`（Codex 执行中）→ `done` / `failed`。`draft` 仍仅为本机问题。与旧示例 submitted/running 分开。
- 同一 request_id 和内容的重复请求返回原 job；内容变更拒绝。一个服务同时处理一项。网络响应丢失后复用原 request_id，已完成任务不自动再次执行；失败后的显式重试创建新 request_id。
- job 包含 id/item_id/repository/question/status/created_at/updated_at/engine/model/source/report/error。模型字段没有运行工具证据时为 null。
- source 包含仓库、README 地址、路径、Git blob SHA、读取时间、是否截断及原字符数。实际提供给 AI 的文字单独保存于 `data/research/sources/<request_id>.json`，不可覆盖；最多 28000 字符。超过接口尺寸上限或不可读取时明确失败。
- report 是结构化 AI 文本：summary、can_do、who_for、first_steps、cost_and_limits、unknowns、next_step。字段完整且落盘成功才变为 done；done 在 UI 表示“整理完成 · 未实测”。作者宣称、AI 建议和未执行步骤分开。
- 任务 JSON 原子保存于 `data/research/jobs/`；服务重启将此前未结束任务标记失败，等待用户决定是否重试，不自动消耗第二次额度。完成结果保持原样。
- 浏览器跟进新增 research_request_id/research/error_message。服务结果存入浏览器副本，刷新后保留，导出包含结果和来源；存储失败不宣称保存成功。更换问题可保留原结果并新建任务。
- AI 执行只接受公开 README 和当前问题。使用本机 Codex 已有登录，忽略个人配置，在空临时目录只读运行，关闭工具/插件/记忆并采用临时会话；不执行仓库命令、不安装项目。遇到不支持的版本/登录/网络/超时/异常输出会失败，不放宽权限重试。
- 这是本机文档整理入口，不是任意 AI 的通用适配器；尚未接 Muse、批量语义推荐或定时付费调用。基础凭据模式拦截不能替代用户检查隐私。


## v0.5：本机试用清单与手动观察

- 只在真实已完成的说明整理任务上提供入口。`getTrialPlan(taskId)` 返回现有清单副本或本机模板，打开面板本身不保存；不访问网络、不调用 AI。
- 初始目标取 report.next_step，步骤取 report.first_steps，截图提示为明确标注的通用模板。没有自动安装、截图或实测。
- `followup.trial_plan` 单独保存：version=1、origin=local-template、research_id、source 副本、goal、steps、shots、outcome、notes、evidence_notes、edited_fields、created_at、updated_at。用户编辑不覆盖原 report、README 或 feed.verification_status。
- outcome 为 not_started / in_progress / worked / blocked / skipped。默认未开始，notes/evidence_notes 为空；worked/blocked 需要非空实际观察。状态只表示手动录入，身份未认证，不等于 AI 核验或用户验收。
- 已记录结果后修改目标/步骤，需同步修改观察或将进度改回未开始；不把旧结果自动套到新计划。
- evidence_notes 只是一段文件名、链接或说明文本，不自动读取这些位置，也不宣称证据文件已附加。shots 是拍摄安排，不是已存在的截图。
- `saveTrialPlan` 校验长度、必填与状态；存储失败恢复原对象，界面保留输入。取消不保存；重复打开同一任务复用同一清单。
- `exportTrialText` 导出清单、手动观察、原整理编号与来源版本，明确区分计划/观察/截图线索。原“复制材料”导出一并包含已保存清单；复制和下载都不产生 AI 送达状态。
- 仅在当前浏览器 localStorage 保留，未建立服务端清单同步、历史版本或截图附件库；清理浏览器或删除跟进前应导出需要保留的清单。


## v0.6：页面资料备份与合并恢复

- `format=personal-feed-backup`、`version=1`、`mode=live|demo`、`exported_at` 和 `state`；state 含 saved_item_ids、hidden_item_ids、followups、profile_override、item_snapshots。仅保留收藏、隐藏或跟进引用的条目快照；不打包全部候选或服务器原始 README。
- `makeBackup` 创建并校验可恢复的 JSON。`parseBackup` 限制文件 4 MB、深度、长度、条数、ID、URL、任务状态、来源引用、结果和试用清单；真实/示例模式不能互导。基础凭据模式拦截不是完整的隐私检测，文件没有身份签名。
- `previewBackup` 只解析和计算新增量，不改本地状态。`restoreBackup` 重新校验原文本和预览时的状态，原子写入同一个 localStorage 键；写入失败恢复原对象。另一个页面已更新资料或预览后发生变化时拒绝恢复，避免覆盖。
- 收藏/隐藏 ID 合并去重；同 ID 的跟进及已有条目快照保留当前版本。默认保留当前偏好，显式选择才采用备份偏好。合并后的资料也必须符合数量/大小限制，确保仍可导出。去重按 ID，不是正文相似度。
- 新导入跟进记录 `imported_backup={exported_at,restored_at,original_status}`，页面及文本导出提示其为未在本轮核验的历史记录。该标签不证明文件作者或 AI 身份真实。
- 导入时移除 research_request_id；活动中的任务改为 failed，提示手动重新整理。恢复本身不轮询历史任务、不调用网络、不安装项目、不改变原始来源或把未实测提升为 verified。
- 来源元数据与报告、手动试用记录保留；这不是服务器 jobs/sources 的恢复接口，也没有跨设备自动同步。未移入服务器来源的历史条目可能无法重新启动整理，需要先获取相应项目。


## v0.7：发文准备与材料编译

- 仅在已完成且含 report 的任务上开放。`writing_brief` 只存 version=1、research_id、format=post|thread|tutorial、audience、angle、created_at、updated_at；不存第二份 report 或生成稿，不新增送达/发布状态。
- `prepareWritingMaterial` 在本机即时读取当前 report、来源和 trial_plan；来源放在明确作为资料的 JSON 块里，外层写作提示区分作者介绍、AI 整理、手动观察和个人意见。不读取文件，不调用 AI 或网络。
- 缺少 completed 手动结果（worked/blocked 且 notes 非空）时，tutorial 输出待实操提纲提示。出现手动结果也明确未独立核验，只有截图线索不等于已上传证据。提示词不能保证接收 AI 的事实准确性。
- `getWritingBrief` 打开不保存；`saveWritingBrief` 校验枚举和长度、检查其他标签页更新，失败恢复旧对象。保存只改变发文准备，不修改任务完成时间、原 report、来源或试用状态。
- UI 提供只保存和保存并复制；复制失败时保留已保存资料并展开可手动复制的文本。取消丢弃本次未保存编辑。表单打开时后台刷新不能覆盖输入。
- 备份沿用可选字段扩展，校验其格式及 research_id 关联。合并仍按任务 ID 保留当前版本；旧备份没有 writing_brief 也可读取。文本导出包含发文选择及个人看法，进口历史标记继续保留。


## v0.8：多来源阅读（数据 schema 0.3）

- 固定来源 GitHub、少数派 RSS、V2EX 分享发现 Atom。NewsNow 托管 API 本轮实测 403，未使用。读取公开订阅，不读取正文、评论、账号资料；外部文字只作为资料，不执行其中的指令。
- `source_buckets` 按来源保存最近成功内容；旧 0.2 缓存在内存迁移，读取本身不发网络请求、不改磁盘。每个来源保留 status、last_success_at、last_attempt_at、next_allowed_at；一次更新只请求已到期来源。GitHub 成功间隔 5 分钟，订阅成功间隔 10 分钟；请求超时 12 秒，订阅返回体限制 2 MB。
- 更新并行读取各源，失败仅保留对应 bucket；完成后原子写缓存，写入失败保留上一版来源时间与内容。汇总 refresh.status 可为 partial，只有全部成功或缓存沿用无失败才为 ok。总 generated_at 表示至少一个来源有新读取，不能替代各来源成功时间。
- 每次成功订阅保存独立来源摘录，记录 source_url、captured_at、items。少数派记录公开摘要，V2EX 不保留完整 content 或作者字段。正文未读不能写成 body_read：可用摘要为 excerpt_only，否则 headline_only。
- published_at 来自订阅发布时间；source_item_time 可记录 Atom updated；captured_at 是本机获取时间。GitHub updated_at 继续表示代码更新时间，资讯不滥用该字段。
- canonical_url 仅规范化同一链接：去锚点和常见跟踪参数、已知站点域名、GitHub 大小写及 .git 后缀。不同链接不按相似标题合并。news ID 为规范链接 SHA256 前 24 位；跨源同链接优先保留 github ID，alias_ids 保持原收藏、隐藏和跟进可关联。
- 合并项保存 source_refs、source_links、evidence_refs；不同来源说法不据此视为相互证实。主条目摘要保留优先来源的原文摘要，其他来源摘录仍可追溯。
- seen_links 最多 5000 个，refresh.new_item_ids/new_count 仅表示本轮成功刷新后首次遇到的规范链接；全部失败时清空本轮新增，冷却期内未刷新则保留前轮标记。与发布时间、热度、用户已读状态无关。
- 首页组合来源过滤、仅新增、关注筛选；只影响展示，不修改缓存或上游范围。收藏和问题可跨批次保存。资讯条目只有手动问题、收藏和导出，不显示或调用仅支持 GitHub README 的 Codex 自动整理。
- 备份版本仍为 1，兼容旧可选字段，接受 news ID 并校验新来源链接与日期。已完成整理的试用/发文入口折叠，原记录保留。

## v0.13 一键收藏与个人想法

首页书签和按关注卡片的“先收藏”只写当前模式对应的浏览器存储。收藏不用创建主题、发起来源请求或模型调用。已收藏重复保存不覆盖原材料，源站条目合并后的别名共享状态；取消收藏不移除主题材料，已写想法保留供重新收藏时使用。

`saved_item_ids` 沿用已有格式；`item_snapshots` 保存材料快照，收藏页与从收藏放入主题优先使用该快照，信息流仍展示最新内容。`saved_item_notes` 是可选映射，键为材料编号，值为 `{note, updated_at}`；想法最多 2000 字，与来源摘要分开。新主题材料预填收藏想法，已有主题不会被后续收藏想法覆盖。

备份版本仍为 1，可接受缺少 `saved_item_notes` 的旧文件，带想法文件必须含对应来源快照。恢复只补本机没有的想法，不覆盖当前想法。写入失败回滚，收藏及想法操作检查其他页面是否产生更新，防止静默覆盖。

“收藏”仅保存站内已有材料，不声明已阅读全文、安装试用或验证。自己的想法仍是手动输入，导出不会把它当成来源事实或已完成结果。

GitHub 今日趋势的真实仓库地址也可沿用 README 阅读入口；资讯和 GitHub 子页面链接仍不进入该读取入口。本轮未加入公开托管的 AI 后端。

## v0.14 收藏搜索与归档

`archived_item_ids` 是可选数组，必须是 `saved_item_ids` 的子集。归档仍属于已收藏，`savedItems` 保持全部收藏的兼容含义；`activeSavedItems`、`archivedItems` 分别用于子页，`archivedItemIds` 包含当前来源条目的别名。旧存储没有该字段时，所有收藏仍在已收藏页，无迁移、清空或新请求。

归档与恢复只改这个状态数组，不改材料快照、个人想法、主题或跟进。取消收藏同步移除对应归档状态；即时撤销在一次事务中恢复收藏和原归档状态。保存失败回滚，其他页面有新写入时拒绝覆盖。

搜索仅遍历当前子页的已保存快照，查询标题、简介、项目名、链接、派生中文用途与例子、适用人群、来源名称、个人想法。查询经过 NFKC 与大小写归一化，以空格分词、全部关键词同时包含的字面匹配，不执行正则或模型检索，不搜索未保存内容及网页全文。搜索词只保存在当前界面，刷新清空；输入最多 200 字，更新结果区时保留搜索输入及焦点，中文组合输入结束后再筛选。

备份版本仍为 1，接受没有 `archived_item_ids` 的旧文件。恢复新的收藏时带上其归档状态；本机已有同一材料（含别名）的收藏或归档选择优先。备份预览分别列出新增收藏总数及其中归档数量，不接受孤立或重复归档标记。搜索和归档不会产生阅读、实测、AI 投递或用户确认记录。

## v0.15 手动正文摘录与可读导出

`saved_item_excerpts` 是可选映射，键为材料编号，值为 `{text, url, recorded_at, origin: user_pasted, verification: not_verified}`。最多 4000 字，来源 URL 必须对应材料的原链接，不允许凭据 URL、脚本 URL 或伪造自动读取／已核验标记。它与来源 `item_snapshots`、个人 `saved_item_notes` 分开保存；同样适用别名、归档、重新收藏和刷新。仅保存手动文本，不请求 URL，也不把 `content_status` 升级为全文已读。

摘录与想法在同一事务中保存，空白清除对应内容；未变化的摘录保留记录时间。存储失败或其他页面新写入时拒绝整次保存，不部分写入；界面保留输入。卡片显示手动来源状态，长于 240 字时可展开完整文本，搜索范围增加已保存摘录。

备份版本仍为 1，兼容没有摘录字段的旧文件；对收藏摘录及主题嵌套副本校验来源、时间、长度和固定手动状态，拒绝孤立引用及伪造来源身份。取消收藏但仍有摘录的材料快照继续纳入备份。合并恢复只补不存在的摘录，不覆盖当前已保存摘录与同编号主题；预览列出新增摘录数量。

`buildTopicMaterial` 改为可阅读的 Markdown，复制给 AI 与下载均只带选中主题。依次分开目标、手动安排、原链接、正文摘录、自己的理由、中文用途和作者简介；来源标识、时间、说明版本等在末尾回查块中保留。缺少目标或结果明确写未填写，不补造任务或实测。动态正文转义并以引用段落展示，链接仅采用 HTTP(S)，导出不执行材料中的命令。来源摘要和粘贴内容仍是参考资料，不构成额外授权。

AI 复制版有分析任务提示；下载版去除该提示，以主题文档开头。不会读取网页正文、上传材料、调用 AI、连接知识库或生成送达回执。基础凭据检查仍不能替代完整隐私审查。

# v0.19 补充：公开内容自动更新与视频来源

## v0.20：SoPilot 的公开推文榜

固定来源 `sopilot-ai`、`sopilot-creators` 读取公开页面的 `category=AI`、`category=Creator`、`range=24h`，只取当页上涨榜，最多 30 条。分类、语言、时间范围或页面格式不符时按失败处理，不以总榜代替；空榜或无有效原帖也不替换旧内容。仅读取网页内公开序列化的数据，不执行脚本、不调用未公开接口，不使用账号、Cookie 或凭据。

`author_name`、`author_handle` 为可选公开作者字段，后者限定 X 账号字符且不包含 `@`。原链接必须匹配该条帖子编号与账号，指向 HTTPS X/Twitter 原帖；链接不可用的条目略过。作者与原帖内容均来自 SoPilot，未独立核对身份。`published_at` 记录原帖发布时间，`source_item_time` 记录该榜单条目的同步时间，`captured_at` 记录本站实际读取时间；缺失时间保持未知。

`source_rank` 为该来源原排名，`heat_label` 使用其 `velocityScore` 标明曝光/小时，不冒充点赞数、总浏览量或跨平台评分。共享原帖合并后仍逐来源保留排名与热度；某来源未知不能套用另一来源的值。`reading_note` 随固定来源定义发布，榜单不代表本站推荐。

帖子摘录、作者、时间与来源随收藏、主题和备份保存；导出注明第三方榜单摘录、未核对原帖及热度，不能成为自动发布、执行命令或安装的授权。原始作者字段不能被导入的用户验证身份替代。X 官方入口仍未接通，SoPilot 来源不等于 X 全站数据。

维护者可用 `mergePublicSourceResults` 发布已实际读取的新来源，只替换明确指定的来源，保留其余旧内容、来源状态、时间与可复用中文介绍。该函数不执行网络或存储；公开审计和有效条目检查通过后再写缓存。维护发布标为 `public-snapshot`，不冒充已观察到的定时执行；之后原定时任务继续读取两个新来源。

## v0.23：今日精选

首页在原来源板块上方增加只读精选，最多5条。按当前分类、已保存的来源显示设置、隐藏条目、只看新增和个人排除词筛选；来源设置尚未保存的编辑不会影响精选。关注词只调整排序，不能让无依据的内容通过门槛。来源更新或筛选条件变化后重新选择，不承诺一天固定五条。

候选只来自已有公开材料，来源本轮可用且最近成功读取、该条实际采集均在72小时内。已知文章发布时间或仓库更新时间也必须在72小时内；未知发布时间明确展示“最近采集；发布未知”，不套用数据包发布时间。无效或未来日期、失败/隐藏来源、纯标题、手动链接、演示、无可用中文用途的材料不入选，仍可按原流程浏览和收藏。

用途需要现有中文说明中同句出现明确操作与对象，并有工具能力或使用方法依据。社会争议、行业泛谈、营销承诺不能只靠“制作视频”等字样入选。GitHub 优先使用与项目匹配的既有中文介绍，保留原简介和整理依据；生成的分类标题不作为能力证据。中文介绍含费用宣称时不用于精选，回退原始中文摘要；没有可用原始摘要就略过。

精选只提供原句或注明截断的用途、规则生成的“阅读提示”、原始来源费用表述、入选理由与来源/时间。费用无依据时写“费用待确认”；免费试用的条件不能变成永久免费，开源、无需注册或AI整理不作为费用证据。文章摘要、第三方推文摘录、未观看的视频简介和AI整理分别标明，一律不当实测。

按用途依据完整度、北京自然日新近程度和关注词排序，不用星数、点赞或不同平台热度作为统一质量分。只合并相同规范化链接、同一完整仓库名或完全相同的长标题；不按相似主题猜测合并。每来源和每用途类别最多2条，候选不足时少选或留空。

选择过程不请求网络、模型或付费服务，不修改原条目。收藏、放进主题仍引用原材料，精选的受众、费用提示和排序不写回原摘要，不混入用户想法。现有来源采集、失败保留、定时安排、资料存储与备份格式不变。
