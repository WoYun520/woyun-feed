## 双击打开，三步开始

Mac 上双击项目里的 **“打开我的信息流.command”**，会启动本机服务并用默认浏览器打开页面。当前电脑的桌面也已放好同名入口。需要已安装 Node.js 22 或更新版本，无需安装第三方依赖。

已启动时直接复用；始终使用 `http://127.0.0.1:3000/`，不因为端口占用偷偷换网址。另一套服务占用时会提示先处理，不自动关闭它或改动资料。入口会出现一个终端窗口，显示打开成功后可以关闭，网站仍在后台运行；重启电脑后再双击即可。没有开机自启；本机资料与公开预览分开。

第一次打开、尚无收藏或主题时，首页展示三步引导。点“先去看看信息”可收起，之后不再自动显示；顶部 **“怎么用”** 可随时重看完整示例，也能直接进入“添加材料”。示例只用来解释填写方式，不自动写入收藏、主题或跟进。

1. **先收下**：点标题到原网站阅读，点书签收藏；站外链接点“添加材料”。
2. **补自己的想法**：在收藏里留下摘录和判断，再放进同一个主题。
3. **带给常用 AI**：打开主题，点“带走这份材料”，检查后复制或导出，在自己的 AI 工具里继续做。

引导偏好保存在当前浏览器，与真实资料和示例资料分开，不进入资料备份。已有收藏、归档、主题或跟进的用户不会被首次引导打断。换浏览器会看到新的引导，也不会自动带过来旧浏览器的收藏；请先备份恢复。手动收起失败时仅本次收起，并明确提示下次可能再次显示。

Mac 若提示访问项目所在文件夹，需要由你在系统窗口允许。没有找到 Node.js、端口被占用、启动失败或浏览器打不开时，入口会显示具体提示。后台启动记录在项目 `.local/startup.log`；这个目录不由网页服务对外提供。移动项目后，桌面链接可能失效，可直接双击新位置里的入口。

看到有用的内容，先点标题旁的书签收下，继续浏览。不必马上起主题名字或填写表单。

1. **点书签**：一键保存到“收藏与跟进”，再次点击可取消，也可以撤销。
2. **稍后整理**：读完原网站，在“已收藏”里补几句有用的正文摘录和自己的想法，或者放进已有／新主题。
3. **带去继续做**：主题里点“带走这份材料”，目标、原链接、手动摘录、自己的想法和原始简介分段带给常用 AI。

收藏会保留当时的标题、链接、简介和中文用途，信息流更新不会覆盖它。自己的想法与原文分开保存，放进主题时可带上；之后修改收藏想法不会改写已有主题。取消收藏会保留主题中的材料，已写的想法也能在重新收藏后继续使用。备份包含这些想法。

收藏、写想法和放进主题只在当前浏览器保存，不调用 AI、不抓取网页全文。换设备前使用“备份与恢复”。

## 从其他网站添加材料

1. 在首页、收藏页或主题里点 **“添加材料”**。
2. 粘贴完整网页链接，填一个自己看得懂的标题。
3. 默认先收进收藏；也可以选已有主题或“新建主题并收藏”，再点 **“保存材料”**。在主题里打开时，会预选当前主题。

“补摘录与想法”是选填项，展开后可留下原文的几句和自己的判断。X、小红书、博客、GitHub 等网页链接都可保存，但本站不会打开或检查页面，不能保证原站公开可读，也不自动读取标题、正文或图片。标题由你填写，固定标为手动添加、未核对原文；没有自动采集时间或实测结果。

材料与摘录支持搜索、归档、刷新保留、主题副本和备份，放进主题后可一起复制或导出。保存到主题时也会收进普通收藏；失败则整次回退，输入仍留在表单，取消不会保存。旧备份仍可恢复。

重复链接会提示使用已有材料，不覆盖原有标题、摘录或想法；比较时忽略 `utm_` 跟踪参数和页面锚点，其他参数保留。短链接与跳转后的网址不会自动合并。只接受 HTTP(S) 链接，拒绝链接内账号密码和常见密钥参数；基础检查并不能识别所有隐私内容，请只保存适合带走的公开材料。

## 读完原文，把有用的几句留下来

1. 点击标题，到原网站阅读。
2. 回到“收藏与跟进”，点“补摘录与想法”。把原文中有用的几句粘贴到“正文关键摘录”，自己的判断写在下方。可只填一项，再一次保存。
3. 点“放进主题”，摘录与想法会自动预填；只需选主题或给新主题起名字。主题保存独立副本，以后修改收藏页不会改写它。已有主题材料也可点“修改摘录与理由”单独补内容。
4. 在主题点“带走这份材料”，检查后“复制给 AI”或“导出 Markdown”。材料按目标、摘录、自己的想法、中文用途和原始简介分段，出处记录放在后面；不会自动发送。

摘录最多 4000 字，想法最多 2000 字；自动关联该材料的原链接和记录时间。手动粘贴固定标为“未核对原文”，不代表本站已经抓取正文或亲自试用。来源原有标题、简介和获取时间保持原样，摘录不会覆盖它们。长摘录可展开，归档后仍保留，也可以按摘录中的词搜索。

取消编辑不保存；保存失败时输入保留，摘录与想法不会只保存一半。取消收藏仍保留已写的摘录，重新收藏后可继续用。备份包含收藏摘录与主题副本；恢复只补本机没有的摘录，已有摘录保留当前版本。基础凭据拦截不是完整的隐私检测，请只保存适合带走的材料。

## 找回收藏，收起暂时用不上的材料

进入“收藏与跟进”，在“搜索收藏”里输入标题、项目名、用途、手动摘录或自己写过的想法。例如输入“字幕 费用”，会找出同时包含这两个词的材料。输入即筛选，不用点提交，也不调用 AI；这里只查已经保存的内容，不搜索网页全文。

暂时用不上的材料点“归档”，会进入旁边的“归档”页。原始摘录、自己的想法和主题关联都保留；需要时点“恢复到收藏”。归档区同样可以搜索。归档和恢复可即时撤销，归档记录也会随备份保存。顶部资料总数仍包含归档，两个子页分别显示各自数量。

旧备份仍可恢复；同一材料已经在本机时，保留本机当前的收藏或归档状态，旧文件不会覆盖新选择。搜索词只在本次页面使用，不保存到备份。

## 从信息到自己的主题

首页用于发现，书签用于先收下。在“收藏与跟进”里再点“放进主题”：选一个已有主题，或只填一个新名字，就能把材料放进去。按关注筛选的详细卡片也可直接放进主题。

顶部“主题工作台”围绕你想做的一件事组织资料。例如“找一个合适的字幕工具”，可以放进几篇方法介绍、几款工具，再记录自己的条件和判断。

1. 首页点书签收藏，再到收藏页点“放进主题”；首次只需起一个名字。目标和收藏理由都可以稍后补。
2. 在主题里点“编辑想法与进度”，写自己的想法。展开后还可补缺口、下一步、结果与收获；都不是自动生成的结论。
3. 点“带走这份材料”，检查内容后“复制给 AI”，或“导出 Markdown”放入支持文本导入的知识库。仍需自己粘贴或导入，没有自动连接外部 AI、知识库或记忆站。

主题保存收藏时的标题、链接、来源简介和时间，以及放入时的手动摘录副本。后来信息流更新、条目不再出现，也不会改写主题里的这份材料；收藏理由、手动摘录与来源简介分开。这里不是网页全文剪藏或附件库。

“移出主题”可以立即撤销，不取消普通收藏，也不影响其他主题。“暂告一段落”需留一句结果或收获，但仍只是手动记录，不代表工具已实测通过。取消编辑不保存，保存失败时表单保留输入。

主题保存在当前浏览器，纳入“备份与恢复”；同编号主题恢复时保留当前版本，旧文件不覆盖新想法。主题资料上限为 60 个主题、每主题 30 条材料，仍受 4 MB 备份上限限制；保存前检查可恢复性，过大时明确拒绝，不部分保存。暂未提供主题删除、跨设备同步、附件上传、AI 自动回写或智能选题。

复制材料只带当前主题，不包含其他收藏与主题；不会调用模型或产生投递回执。请检查自己的输入，不要填写密码、密钥或私人原件；基础凭据检查不等于完整隐私检测。

## 怎么用

1. Mac 双击“打开我的信息流.command”；也可在项目的 `frontend` 文件夹运行 `npm start`（需要 Node.js 22 或更新版本，无需安装第三方依赖）。打开 http://127.0.0.1:3000/。
2. 本机版点击“更新内容”，分别尝试获取已配置频道的公开内容。以后打开页面先读本机缓存，不自动更新；公开网站的定时更新在云端独立进行。
3. 默认按来源板块浏览，直接点击标题到原站阅读；标题旁书签按钮用于一键收藏。分类按钮切换板块，“只看本次新增”只展示这轮新出现的链接。
4. 如需初筛，在“我的关注”填写想看和少看的方向，多个词用逗号分隔；点“按我的关注筛选”查看关键词匹配结果。这里仍可用“信息来源”选择频道，用“全部候选”分批看完未匹配内容；单一热榜沿用该站榜单顺序。
5. 感兴趣就打开来源链接或点“值得关注”。搜索入口标为“查看热搜”，讨论入口标为“查看讨论”，不把它们当成文章原文。所有条目都可保存问题和导出材料；“GitHub 小型工具”的项目还可点“继续查一查”→“用 Codex 整理”，读项目说明并返回通俗中文结果。“GitHub 今日趋势”里的真实仓库链接也支持此入口。
6. 收藏、问题和已完成的整理都在“收藏与跟进”。原有试用清单和发文准备收在已完成任务的“更多操作：试用与发文”里，需要时再展开。
7. 换浏览器或清理数据前，点击“备份与恢复”→“备份到电脑”；恢复时先预览，再合并。

整理入口需要本机已安装并登录 Codex CLI，使用已有账号的额度；这不是免费的独立 AI 服务，也不要求再填 API 密钥。尚未准备 Codex 时，可以“只保存问题”，再复制或导出材料给自己的 AI。

保持本机服务运行，关闭页面不影响已启动的整理。关闭服务后本机网页不可用；双击入口可再次启动。重启遇到未完成任务会提示手动重试，不自动再次调用 AI。本机版没有开机自启；独立公开网站无需你的本机服务。

## 整理会给我什么

用途、作者提到的能力、适合谁、第一步怎么用、费用与限制，以及还要核对的事。只读取选中的公开项目 README，不安装项目、不读你的其他项目文件、不自动浏览其他链接。长文最多送入前 28000 个字符，会明确标成摘录。

这是 AI 对说明的整理，可能出错，不等于工具实测或推荐担保。作者的介绍与 AI 建议分开显示，保留来源版本和读取时间。界面一次启动一项；重复连接同一请求不会重复启动。已完成的同一问题直接显示原结果，换个问题会新建一份整理，保留原结果。

问题中不要填写密码或私人材料。常见凭据格式有基础拦截，不代表能自动识别所有敏感信息。

## 从说明到亲自试用

“准备试用清单”是本机模板，不会再次调用 AI 或消耗额度。它沿用原有 AI 建议，补上通用截图提示；你可修改目标与步骤、记录实际观察、备注截图文件名或公开材料链接。

清单不会安装或运行工具，也不会生成、上传或读取截图。没试过时，进度保持“还没开始”、实际观察留空。填写“跑通了”或“卡住了”需要补一句实际观察，仍属于手动记录，不是自动核验。更换目标或步骤后，旧观察不能直接充当新试用结果。

AI 的原始整理与试用清单分开保存；手动记录不修改原项目的“未实测”标记。清单目前仅保存在当前浏览器的跟进条目中，清理站点数据或删除任务会移除它，长期保留请先备份或导出。

## 从试用材料到发文准备

“准备发文”会把当前项目说明、来源链接、试用记录和截图安排整理为一份写作材料，另外保存你选的文章形式、目标读者和个人看法。每次预览/复制都读取当前已保存资料，不把过去的材料快照当作最新结果。

可以不填个人看法直接复制，但材料会注明尚无个人立场，要求 AI 不替你编经历。没有完成的试用记录时，图文教程只准备待实操提纲；已有手动记录也不等于独立核验。截图备注不会被读取或上传，原作者的说明与 AI 整理、手动观察保持分开。

“只保存”方便稍后继续；“保存并复制材料”会先保存选择，再复制到剪贴板。浏览器不允许复制时，已保存的内容保留，并展开文本供手动复制。取消不保存本次修改。

这一步是本机模板整理，不再次调用模型。你需要把材料粘贴到 Muse 或其他 AI 才能生成文章，随后自行检查、修改和发布；目前没有 Muse 自动接入、自动写稿或自动发布。写作要求只是约束提示，不能保证接收的 AI 不出错。

## 备份与恢复

“收藏与跟进”和“我的关注”都有入口。备份包含已保存的收藏、手动摘录与想法、主题材料、隐藏条目、关注偏好、跟进问题、页面中的 AI 整理结果、试用清单、发文准备和相关来源信息。文件只在本机生成、读取，不上传服务器，也不调用 AI。下载后请检查浏览器下载记录，确认 JSON 文件已保存。

恢复分两步：先选文件看新增数量，再确认合并。同编号的跟进保留当前版本，避免旧备份盖掉新写的观察；重复恢复不会再增加同一份记录。默认保留当前关注偏好，需要时再勾选“同时恢复备份里的关注偏好”。不是同编号的任务仍会分别保留。

恢复的内容标为历史记录，本轮没有重新核验。备份中未完成的 AI 任务会显示为未完成、需要手动重试，不会自动再次消耗额度。备份只支持本应用生成的 JSON、最多 4 MB；真实资料和示例资料分开恢复。预览后资料有变化，需要重新预览。

这是手动的页面资料备份，不是账号同步或整个项目备份：不包含完整 README、服务器原始来源文件、安装的软件及截图原件。要迁移整个项目，还需另行保留项目文件夹和 `data/`；只恢复页面备份不会重建服务器资料库。恢复后若要重新整理不在当前服务器来源中的项目，需要先重新获取该项目。

请自己保管文件并检查私人信息。常见密钥格式有基础拦截，不代表完整隐私检测。格式错误、容量不足或资料超过支持范围时，不会部分写入或清空已有记录。

- 固定获取 GitHub 标为 `productivity` 的公开项目，100–5000 star、近 180 天有代码更新，排除已归档项目和 fork。

- 少数派、V2EX、Solidot、Product Hunt、36氪、爱范儿和小众软件读取原站 RSS/Atom；其余频道读取原站公开列表或公开数据接口。除 GitHub 小型工具外，成功获取后间隔 10 分钟。每项只保留标题、链接、可用摘要及时间；不读取完整正文、评论和图片，原文可能需要会员或登录。
- Hacker News 使用 [官方公开 API](https://github.com/HackerNews/API)，按榜单前 10 个编号串行读取条目，保留原位置；榜单可能含招聘条目，已删除或失效项略过后不补位。每次请求最多 4 秒，整源最多 20 秒；任一条读取失败就保留该来源整批旧内容，不把部分结果标为更新成功。2026-10-02 的本机完整原生读取仍在首条内容请求时超时；人工读取成功仅用于核对，尚不能据此宣称本机或云端正式读取接通。
- 热榜保存该来源本次返回的位置；知乎提供的热度文字直接标为“来源标注”，不换算成跨平台分数。百度热搜打开搜索结果，头条打开话题页，知乎和 Hacker News 打开讨论页。排名、热度和标题都不是内容真实性或质量证明。
- SoPilot 读取 AI、自媒体分类的公开 24 小时上涨榜，按其每小时曝光排序，每榜最多 30 条。本轮实际读取各 30 条，共 60 条。帖子发布时间、SoPilot 榜单更新时间、本站获取时间分开保存；作者与热度来自该第三方榜单，未独立核对 X 原帖、作者身份或统计数据。点击帖子打开 X 原链接，收藏、主题与备份保留这份来源记录；复制或导出时注明没有读取完整原帖。
- 相同链接去掉常见跟踪参数与锚点后合并，保留所有来源及对应摘录记录。标题相似但链接不同的条目仍各自保留，没有语义去重。
- “本次新增”表示最近一轮实际更新中，未在本机近期记录出现过的链接，不等于刚发表、热门或已经读过；最多保留最近 5000 个已见链接。等待间隔内点击更新不会清掉上一轮标记。
- 单个来源失败时沿用该来源的旧内容，其余来源仍可更新。侧栏分别显示最近读到内容的时间；不能把本轮总更新时间理解为所有来源都已刷新。

部分来源的地址和字段映射参考 [NewsNow](https://github.com/newsnext/newsnow) 的开源实现，已保留 [MIT 许可及引用说明](THIRD_PARTY_NOTICES.md)。本机和云端读取固定公开地址，不依赖 NewsNow 托管 API；SoPilot 读取其公开榜单页面，不通过它访问 X 私人账号或原帖全文。之前托管接口返回 403 的历史没有改写为接通；今日热榜仍未接入，不使用登录 Cookie 或绕过访问限制。

## 保存在哪里

- 最新资料：`data/live-feed.json`；成功抓取的来源摘录：`data/source-snapshots/`。每次摘录单独保存，标题、简介、star、时间和查询来源可以追溯。
- 收藏、隐藏、个人偏好、主题工作台、跟进草稿、试用清单与发文准备：当前浏览器本地存储 `personal-feed:live:v1`。收藏和跟进会附带内容副本；主题各自保留收藏时的材料，即使下次更新不再出现该项目，也不会失去这份材料。
- 整理进度及结果：`data/research/jobs/`；本次实际读取的 README 文字或摘录：`data/research/sources/`，每次单独保存，不被 AI 摘要覆盖。
- 浏览器清理站点数据会清掉收藏与跟进的页面索引；可通过本版导出的 JSON 备份恢复页面资料。本机整理文件仍在，但没有直接扫描服务器文件重建全部列表的入口。换浏览器或换端口不共享页面收藏与列表；可手动备份、恢复，尚未做账号同步。
- 演示稿保留在 `http://127.0.0.1:3000/?demo=1`，使用原有独立存储 `personal-feed:demo:v1`，与真实资料分开。
